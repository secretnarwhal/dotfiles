# Headphone Channel Swap Configuration

This document outlines the setup used to swap the Left and Right audio channels on Arch Linux using PipeWire and Hyprland. 

## The Objective
To flip the Left (FL) and Right (FR) audio channels specifically when headphones are plugged into the 3.5mm jack, and to provide a seamless way to toggle this feature on and off via a keyboard shortcut.

## Current Audio State
The system uses **PipeWire** as the audio server and **WirePlumber** as the session manager. 
When physical devices are plugged in, PipeWire exposes them as "Sinks" (Outputs).
To achieve the channel swap without messing up the hardware mappings, a **Virtual Sink** was created using a PipeWire Filter Chain.

### Active Audio Sinks
1. **Physical Sink:** `Ryzen HD Audio Controller Headphones` (or `Speaker` when unplugged). This is the raw hardware output.
2. **Virtual Sink:** `Headphones Swapped` (`headphone_swap_sink`). This sink is generated by a custom PipeWire configuration.

## 1. The PipeWire Filter Chain (The Core Engine)
To swap the channels, a PipeWire module called `libpipewire-module-filter-chain` is used. 
**File Location:** `~/.config/pipewire/pipewire.conf.d/headphone-swap.conf`

**How it works:**
* It creates a virtual audio device named "Headphones Swapped".
* It intercepts the audio streams going into it.
* In the `filter.graph`, it takes the Left input (`copy_l:In`) and routes it to the Right output (`copy_r:Out`), and takes the Right input (`copy_r:In`) and routes it to the Left output (`copy_l:Out`).
* Finally, the `playback.props` aggressively target the physical ALSA output (`alsa_output.pci-0000_04_00.6.HiFi__Headphones__sink`) to push the flipped audio out to the physical jack.

## 2. The Toggle Script (The Brains)
Because you only want this active sometimes, a bash script was created to dynamically switch the default audio output between the normal physical sink and the virtual swapped sink.
**File Location:** `~/.config/viegphunt/toggle_audio_swap.sh` (symlinked from `~/dotfiles/.config/viegphunt/toggle_audio_swap.sh`)

**Script Logic:**
1. Uses `wpctl status` to find the dynamic node IDs of both the `headphone_swap_sink` and the physical hardware sink (checking for either "Headphones" or "Speaker").
2. Identifies which sink is currently marked as the default (indicated by an `*` in the `wpctl status` output).
3. If the virtual swapped sink is default, it switches back to the physical hardware sink.
4. If the physical sink is default, it switches to the virtual swapped sink.
5. Issues a desktop notification via `notify-send` confirming the new state ("Swapped Mode (Swap ON) 🔄" or "Normal Mode (Swap OFF) 🔊").

## 3. The Hyprland Keybinding (The Trigger)
To make switching instantaneous, the toggle script is bound to a key combination in Hyprland.
**File Location:** `~/dotfiles/.config/hypr/conf/keybinding.conf`

**Keybind:** `SUPER + F10`
* **Configuration Line:** `bind = $mainMod, F10, exec, ~/.config/viegphunt/toggle_audio_swap.sh`

## Troubleshooting
* **"Headphones Swapped" is missing from pavucontrol/wpctl:** The virtual sink sometimes unloads or crashes if the physical target completely disappears from the ALSA driver unexpectedly. Running `systemctl --user restart pipewire` will force it to reload. The toggle script automatically attempts to do this if it cannot find the swapped sink ID.
* **Volume Control:** Because the swapped audio routes through a virtual sink, volume keys should control the *default* sink (which the toggle script manages). Ensure your volume media keys in `keybinding.conf` are configured to target `@DEFAULT_AUDIO_SINK@`.
